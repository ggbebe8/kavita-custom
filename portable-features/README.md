# Kavita 수정 기능만 다른 환경에 설치하기

## PWA 앱 설치

**HTTPS를 생략해도 기본 설치와 추가 리더 기능은 모두 사용할 수 있습니다.** 기본 설치 스크립트는 HTTPS 설정이나 기존 다른 서비스의 프록시 변경을 요구하지 않습니다. HTTPS는 외부 주소에서 PWA 앱 설치를 원할 때 추가하는 선택 사항입니다.

PWA 매니페스트(`/site.webmanifest`)와 실제 192px/512px PNG 아이콘을 포함합니다. 설치 시 앱 이름은 Kavita이며 `standalone` 모드로 실행합니다. 기존 계정·읽기 위치·메모는 같은 Kavita 서버를 사용합니다. 별도 오프라인 책 저장/서비스 워커 캐시는 추가하지 않습니다.

외부 도메인이나 LAN IP에서는 **유효한 인증서가 있는 HTTPS 주소**가 필요합니다. `http://localhost:5000` 같은 실제 기기 자신의 루프백 주소는 개발용 예외입니다. 다른 컴퓨터의 LAN IP를 localhost로 취급하지 않습니다. 도메인/포트는 파일에 고정하지 않았으며 매니페스트의 시작 주소·범위·앱 ID는 현재 출처의 `/`입니다.

HTTPS는 설치할 환경의 프록시에서 제공하세요. 같은 호스트에서 Caddy를 사용할 때의 예시는 `proxy/https.Caddyfile.example`입니다. 실제 도메인으로 바꾸고 DNS 및 80/443 접근을 준비합니다. Docker 안의 Caddy라면 연결 가능한 게이트웨이나 공유 네트워크의 Kavita 프록시 주소를 upstream으로 지정해야 합니다. 이미 80/443을 사용하는 다른 서비스가 있다면 기존 프록시에 별도 호스트를 추가하며 기존 구성을 보존하세요. HTTPS 앞단이 `X-Forwarded-Proto: https`를 설정하면 추가 Nginx가 Kavita까지 전달합니다.

Android Chrome에서 HTTPS 주소를 열고 로그인한 뒤 브라우저 메뉴의 **앱 설치** 또는 **홈 화면에 추가**를 선택하세요. 설치 후 아이콘으로 실행해 스와이프·페이지 이동·하이라이트·메모를 확인합니다. HTTP에서 HTTPS 또는 다른 호스트로 옮기면 다시 로그인하고 브라우저별 추가 설정을 다시 켜야 할 수 있습니다. 서버의 기존 계정/메모는 유지됩니다.

Chromium 검사에서 매니페스트 파싱, 아이콘 실제 크기, 깊은 리더 경로에서도 루트 앱 범위, 루프백 설치 조건 오류 없음 등을 확인했습니다. 실제 Android 설치 여부는 기기에서 확인해야 합니다. 설치가 안 되면 HTTPS 인증서 경고가 없는지 먼저 확인합니다. 설치만으로 오프라인 EPUB 읽기가 제공되지는 않습니다.

공식 설치 조건: https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable

## 전체 페이지 번호로 이동

오른쪽 아래에 추가된 **현재 / 전체 페이지** 숫자를 터치하거나 클릭하면 **전체 페이지로 이동** 팝업이 열립니다. 이동할 번호를 입력하고 확인하거나 Enter를 누르세요. 현재 화면·글꼴 기준의 전체 페이지 번호입니다. 기존 Kavita 하단의 콘텐츠 파일 번호 링크는 원래 동작을 유지합니다.

- 전체 계산이 끝나 숫자가 표시된 상태에서 사용할 수 있습니다. `…` 또는 `—` 상태와 로딩/다른 팝업이 열린 동안에는 사용할 수 없습니다.
- 1부터 표시된 전체 페이지 수까지의 정수만 허용하며, 취소하면 현재 위치를 유지합니다.
- 기존 Kavita 페이지 이동 팝업과 장 전환을 사용하고, 해당 장이 로드된 뒤 장 안의 화면 위치를 맞춥니다. 긴 장이나 이미지 로딩에서는 잠깐 시간이 걸릴 수 있습니다.
- 몰입 모드에서 메뉴가 숨겨져 있어도 사용할 수 있으며, 이동/취소 후 메뉴를 다시 숨깁니다.
- 팝업이 열린 동안 화면 크기·글꼴·레이아웃이 바뀌면 팝업을 닫고 재계산 후 이동하세요. 이동 준비 중 새 읽기 조작을 하면 지연된 화면 이동을 취소합니다.
- 기존 리더의 진행 상태 저장을 사용하며 추가 진행 저장 API를 만들지 않습니다. 페이지 계산 캐시는 기존처럼 14일간 유지합니다.

검증: Chromium에서 같은 장/다른 장, 첫·마지막 페이지, 입력 오류, Enter/취소, 1열/2열, 몰입 모드 및 기존 읽기 위치 테스트를 확인했습니다. 실제 Kavita의 `브람스를 좋아하세요`에서도 13·14페이지, 첫·마지막 페이지 및 몰입 모드 이동을 확인했습니다. 테스트 브라우저의 API 쓰기는 차단했습니다. 실제 Android는 새로고침 후 숫자를 눌러 이동하고 기존 스와이프·메모·읽기 위치도 확인하세요.

## 높이에 따라 페이지 넘기기

새로고침 후 EPUB 리더의 설정 메뉴를 엽니다. 글자 크기 바로 아래의 **높이에 따라 페이지 넘기기**를 켜세요. 기본값은 꺼짐입니다.

- 화면 좌우 각 20%에서 위쪽 1/3을 탭/클릭하면 이전 페이지, 아래쪽 2/3이면 다음 페이지입니다. 높이 기준은 현재 브라우저 화면입니다.
- 가운데 60%는 기존 메뉴 동작을 유지합니다. 상하 메뉴 버튼은 원래 기능으로 동작합니다.
- 기존 터치 페이지 넘김 옵션과 독립적으로 동작합니다. 끄면 기존 좌우 영역 동작으로 복구됩니다.
- EPUB 1열/2열에 적용합니다. PDF와 세로 스크롤 모드에는 적용하지 않습니다.
- 선택 중인 텍스트, 링크, 입력, 북마크/하이라이트/각주 컨트롤, 설정·목차·메모 팝업, 로딩, 드래그, 두 손가락 터치는 페이지 넘김 대상에서 제외합니다. 기존 스와이프 방향은 그대로 유지합니다.
- 설정은 같은 사이트/브라우저에서 계정별로 저장합니다. 다른 기기에는 자동 동기화되지 않으며, 브라우저 저장소가 차단되면 현재 탭에서만 유지됩니다.

Android/Windows/Ubuntu 터치 브라우저와 PC 마우스에서 위쪽 좌우, 아래쪽 좌우, 가운데 메뉴, 몰입 모드, 옵션 끄기를 확인하세요. Chromium 자동 테스트로 영역 경계와 충돌 방지를 검증하며 실제 Android 확인은 별도로 필요합니다.

이 패키지는 데이터 백업이 아니라 **수정한 기능의 재사용 패키지**다. 책·config·계정·메모·DB·D: 경로를 포함하지 않는다. Android 및 Windows/Ubuntu 터치 브라우저의 EPUB 스와이프, 몰입 모드 지원, 상단 단축키 아이콘 왼쪽의 전체화면 토글 버튼, 오른쪽 하단의 책 전체 화면 페이지 표시와 재계산 캐시, Nginx의 JS 주입과 같은 화면 설정에서의 읽기 위치 복원 보완을 포함한다.

현재 검증한 Kavita와 Nginx의 이미지 digest를 고정하여 같은 프런트엔드 구조를 다시 사용한다. 기능은 브라우저의 화면·글꼴에 따라 계산한다. 1열/2열 모드에서 동작하고, 텍스트 선택·팝업·입력·다중 터치·화면 가장자리·PDF·세로 스크롤에서는 스와이프를 제외한다.

## 보관할 파일

`kavita-features.tar.gz`와 `kavita-features.tar.gz.sha256` 두 파일을 다른 컴퓨터 또는 외부 저장소에 보관한다. 이 파일만으로 데이터가 복원되지는 않는다. 계정·메모를 유지할 때는 기존 config를 별도로 준비한다. 책과 config를 새로 사용할 수도 있다.

## 새 환경의 준비

- Linux 또는 Windows의 WSL/Docker Linux 컨테이너 환경
- Docker Engine/Compose와 Python 3.12 이상
- 경로 옵션을 생략하면 기본 책·config 폴더를 자동 생성. 기존 폴더를 지정할 경우 미리 준비
- 고정 이미지를 다운로드할 인터넷 연결

새 설치에서 빈 config를 사용할 경우 처음 실행할 때 새 계정을 설정한다. 기존 계정/메모를 유지하려면 기존 config를 지정한다. **같은 config를 사용하는 기존 Kavita와 새 Kavita를 동시에 실행하지 않는다.** 기존 서비스를 교체할 때는 데이터를 백업하고 계획한 중단 시간에 전환한다.

WSL에서는 `D:\Books` 같은 Windows 표기 대신 `/mnt/d/Books`를 지정한다. D:를 사용할 필요는 없으며, 아래 `/srv/...` 역시 예시다.

## 설치

새 환경에 보관한 두 파일을 가져온 뒤 원하는 작업 폴더에서 실행한다.

```bash
sha256sum -c kavita-features.tar.gz.sha256
tar -xzf kavita-features.tar.gz
```

Git으로 사용할 때는 `portable-features` 폴더의 내용(install.py, README.md, images.json, manifest.json, proxy)을 저장소 최상위에 올린다. 책·config·DB는 Git에 올리지 않는다. 다른 서버에서 `git clone <저장소URL> kavita-features` 후 `python3 kavita-features/install.py`를 실행한다.

기본 설치는 옵션 없이 실행한다.

```bash
python3 portable-features/install.py
```

기본값:

| 항목 | 기본값 |
|---|---|
| 설치 폴더 | `~/docker/kavita-custom` |
| 책 폴더 | 설치 폴더의 `books` (자동 생성) |
| config 폴더 | 설치 폴더의 `config` (자동 생성) |
| 서비스 포트 | `5000` |

일부 또는 모든 값을 입력하면 해당 값만 사용한다. `--target`만 바꾸면 기본 books/config도 새 설치 폴더 아래에 생성한다. `--books-dir` 또는 `--config-dir`로 기존 경로를 지정하면 그 경로는 먼저 존재해야 한다. 설치 대상 폴더는 새 경로여야 한다.

```bash
python3 portable-features/install.py \
  --books-dir /srv/my-books \
  --config-dir /srv/my-kavita-config \
  --target "$HOME/docker/kavita-custom" \
  --port 5000
```

이 명령은 파일의 체크섬을 확인하고 지정한 경로를 사용한 Compose를 생성한다. 사용자 데이터는 복사하거나 수정하지 않으며 컨테이너도 시작하지 않는다. 기존 대상 폴더는 덮어쓰지 않는다. 생성한 `compose.yaml`은 JSON 형태의 유효한 YAML이다.

설정을 확인한 후 새 환경에서 실행한다.

```bash
cd "$HOME/docker/kavita-custom"
docker compose -p kavita-custom -f compose.yaml config --quiet
docker compose -p kavita-custom -f compose.yaml pull
docker compose -p kavita-custom -f compose.yaml up -d
docker compose -p kavita-custom -f compose.yaml ps
curl -fsS http://localhost:5000/api/health
```

포트를 변경했으면 health와 브라우저 주소에도 같은 포트를 사용한다. 프로젝트 이름 `kavita-custom`은 여러 설치마다 다르게 지정할 수 있으며 이후 관리/롤백에서도 같은 이름을 쓴다. 컨테이너 이름을 고정하지 않으므로 다른 프로젝트와 이름이 충돌하지 않는다. 호스트 포트와 config는 공유하지 않는다. 로컬 접근만 허용하려면 설치 명령에 `--bind 127.0.0.1`을 추가한다. 기본은 `0.0.0.0`이다.

## 책 경로를 웹페이지에서 설정

기본 설치에서는 `~/docker/kavita-custom/books`에 책 파일이나 하위 폴더를 넣는다. 예를 들어 `books/소설`과 `books/만화`를 만든 뒤 Kavita 웹의 라이브러리 관리에서 `/books/소설`, `/books/만화`를 각각 등록하면 된다. 새 라이브러리를 추가하거나 하위 폴더를 선택할 때 설치 스크립트를 다시 실행할 필요가 없다.

`--books-dir`을 입력해도 지정한 서버 폴더는 웹에서 `/books`로 보인다. 연결된 폴더 밖의 다른 서버 경로를 사용하려면 Compose의 Docker 마운트 변경이 필요하다. config·DB 저장 위치와 서비스 포트는 웹에서 바꾸는 항목이 아니며 Docker 설정에서 관리한다.

## 동작 확인

1. 기존 또는 새 계정으로 접속해 EPUB을 1열/2열로 연다.
2. 새로고침 후 좌우 스와이프와 몰입 모드 스와이프를 확인한다. 상단 단축키 아이콘 왼쪽의 전체화면 버튼을 누르면 전체화면, 다시 누르면 원래 화면으로 돌아오는지 확인한다.
3. 오른쪽 페이지 표시가 `…`에서 숫자로 바뀌는지 확인한다. 첫 계산에서는 측정 iframe/CSS를 재사용하고 최대 2개 본문을 미리 가져온다. 긴 책은 여전히 시간이 걸릴 수 있고, 같은 책·설정으로 다시 열면 숫자 캐시를 재사용한다. 캐시는 같은 브라우저/사이트에 14일간, 최대 30개 설정을 보관하고 설정/책 메타데이터가 바뀌면 재계산한다. 본문·인증정보는 저장하지 않는다.
4. 목차 이동·글꼴 변경·회전 후 전체 숫자와 위치를 확인한다.
5. 선택·메모 작성·설정·목차에서 오작동하지 않는지 확인한다. 기존 config를 사용하면 읽기 위치와 메모도 확인한다.

사이트 루트(`/`)에서 서비스하는 구성이다. `/kavita/` 같은 하위 경로 설치는 별도 조정이 필요하다. 상위 프록시가 강한 CSP로 스크립트나 측정 iframe을 차단하면 해당 환경도 확인해야 한다. 임의의 미래 Kavita 버전 또는 모든 EPUB/브라우저에서 완벽한 호환성을 보장하는 패키지는 아니다. 고정된 같은 버전에서 기능을 재현하고 경로·포트를 바꿀 수 있도록 만든 구성이다. 운영 중인 더 최신 Kavita의 DB를 이 고정 버전에 연결해 다운그레이드하지 않는다.

Docker·WSL 설치, Windows 자동 시작, SSH 터널, 도메인/TLS와 방화벽은 새 서버의 환경에 맞춰 별도로 설정한다. 두 컨테이너의 `unless-stopped` 재시작 정책은 포함되어 있다.

## 기능만 제거하기

원하는 중단 시간에 프록시를 제거하고 동일 config·이미지로 직접 Kavita를 실행한다. 설치 시 지정한 호스트 포트를 유지한다.

```bash
docker compose -p kavita-custom -f compose.yaml stop swipe-proxy
docker compose -p kavita-custom -f compose.yaml rm -f swipe-proxy
docker compose -p kavita-custom -f compose.original.yaml up -d --pull never kavita
```

책/DB/볼륨을 삭제하거나 `down -v`를 실행하지 않는다.

## 기능을 수정한 뒤 새 패키지 만들기

원본 작업 프로젝트에서 실행한다.

```bash
python3 scripts/export-features.py
```

최신 JS·Nginx 설정·설치 스크립트·이 안내를 다시 묶는다. 이미지 버전 변경은 `scripts/export-features.py`의 고정 digest와 새 버전의 DOM/CSP/기능을 먼저 검증한다. 현재 운영 서비스는 패키지 생성으로 변경되지 않는다.

읽기 위치 보완은 변경 이후 저장하는 위치부터 적용한다. 같은 화면·글꼴 설정에서는 구간 내 화면 위치를 복원하고, 설정이 다르면 기존 본문 요소 기반 복원을 사용한다. 기존 위치 저장 API와 유효한 XPath를 사용하며 별도 저장 요청을 만들지 않는다. 실제 책에서 몇 페이지 읽고 종료 후 재열어 위치를 확인한다.

구간 이동에서는 계산한 전체 합계를 유지하며 해당 구간의 실제 측정 차이만 보정한다. 글꼴·화면 등 실제 설정이나 책 파일 정보가 바뀌면 다시 계산한다. 몰입 모드의 메뉴 복원은 구간 로딩 완료 후에 수행하고, 사용자가 페이지를 옮긴 후에는 늦은 초기 위치 응답으로 되돌리지 않는다.

북마크가 없는 이미지의 빈 책갈피 모양 추가 버튼은 기본 숨김이며, 이미지를 클릭/탭할 때만 나타난다. 실제 저장된 이미지/텍스트 북마크는 계속 표시한다. 단순 이미지 탭은 북마크를 저장하지 않으며 추가 버튼을 눌러야 기존 Kavita 방식으로 저장한다.

### 2026-10-14 집중 모드 터치 유지 보완

연속 넘김 제한 650ms와 클릭 차단 500ms 사이의 틈에서 터치가 기본 메뉴 토글로 전달되는 문제를 Chromium 터치 입력으로 재현했습니다. 클릭 차단을 650ms로 맞추고, 페이지 전환 중의 본문 클릭도 차단합니다. 링크/입력/버튼의 기존 조작은 제외합니다.

장 로딩이 5초를 넘으면 임시 메뉴 가림을 해제하던 제한도 제거했습니다. 로딩 완료 또는 리더 종료까지 가림을 유지하며, 완료 후 숨김 상태로 복구합니다. 빠른 재터치, 5.5초 장 로딩, 로딩 중 재터치, 이후 의도적인 가운데 메뉴 탭, 기존 스와이프와 페이지 번호 이동을 테스트했습니다. 실제 Android에서는 새로고침 또는 PWA 재실행 후 확인하세요.

### 2026-10-14 빠른 연속 탭

높이에 따라 페이지 넘기기 옵션에서 새 탭은 650ms 대기 없이 받습니다. 스와이프 뒤에 발생하는 중복 클릭 차단은 유지하고, 새로운 포인터 누름/해제가 확인된 탭은 별도로 처리합니다. 기본 좌우 탭 옵션을 변경하지 않으며 스와이프 인식 조건도 유지합니다.

페이지 버튼 처리는 한 번씩 직렬 실행합니다. 장 로딩 중 추가 탭을 최대 3개 대기시키며, 현재 실행 중인 한 번을 포함하면 최대 4번입니다. 입력한 다음/이전 방향 순서를 유지하고 10초가 지난 대기 입력은 버립니다. 가운데 영역, 링크/입력/설정 조작, 드래그·선택·다중 터치, 리더 종료·책 주소 변경 시 대기 입력을 취소합니다. 로딩 도중 가운데 탭은 대기만 취소하고 임시 메뉴를 토글하지 않습니다. 전환 완료 후 가운데 탭으로 기존 메뉴를 열 수 있습니다.

Chromium에서 0.14초 간격 4회 탭, 3개 대기 한도, 느린 장의 순차 처리, 방향 순서, 대기 취소와 집중 모드 유지, 기존 페이지 번호 이동·읽기 위치 복원을 검증했습니다. 실제 Android에서는 사이트 새로고침/PWA 재실행 후 확인하세요.
