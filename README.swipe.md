# 터치스크린 EPUB swipe

## PWA 앱 설치

PWA 매니페스트(`/site.webmanifest`)와 실제 192px/512px PNG 아이콘을 포함합니다. 설치 시 앱 이름은 Kavita이며 `standalone` 모드로 실행합니다. 기존 계정·읽기 위치·메모는 같은 Kavita 서버를 사용합니다. HTTPS에서 선택한 EPUB을 오프라인으로 저장하고 읽기 위치·메모를 재연결 시 동기화할 수 있습니다. 서비스 워커는 공개 화면 파일만 캐시하며, 책과 변경은 계정별로 기기에 보관합니다. 자세한 사용법은 [OFFLINE.md](OFFLINE.md)를 확인하세요.

외부 도메인이나 LAN IP에서는 **유효한 인증서가 있는 HTTPS 주소**가 필요합니다. `http://localhost:5000` 같은 실제 기기 자신의 루프백 주소는 개발용 예외입니다. 다른 컴퓨터의 LAN IP를 localhost로 취급하지 않습니다. 도메인/포트는 파일에 고정하지 않았으며 매니페스트의 시작 주소·범위·앱 ID는 현재 출처의 `/`입니다.

HTTPS는 설치할 환경의 프록시에서 제공하세요. 같은 호스트에서 Caddy를 사용할 때의 예시는 `proxy/https.Caddyfile.example`입니다. 실제 도메인으로 바꾸고 DNS 및 80/443 접근을 준비합니다. Docker 안의 Caddy라면 연결 가능한 게이트웨이나 공유 네트워크의 Kavita 프록시 주소를 upstream으로 지정해야 합니다. 이미 80/443을 사용하는 다른 서비스가 있다면 기존 프록시에 별도 호스트를 추가하며 기존 구성을 보존하세요. HTTPS 앞단이 `X-Forwarded-Proto: https`를 설정하면 추가 Nginx가 Kavita까지 전달합니다.

Android Chrome에서 HTTPS 주소를 열고 로그인한 뒤 브라우저 메뉴의 **앱 설치** 또는 **홈 화면에 추가**를 선택하세요. 설치 후 아이콘으로 실행해 스와이프·페이지 이동·하이라이트·메모를 확인합니다. HTTP에서 HTTPS 또는 다른 호스트로 옮기면 다시 로그인하고 브라우저별 추가 설정을 다시 켜야 할 수 있습니다. 서버의 기존 계정/메모는 유지됩니다.

Chromium 검사에서 매니페스트 파싱, 아이콘 실제 크기, 깊은 리더 경로에서도 루트 앱 범위, 루프백 설치 조건 오류 없음 등을 확인했습니다. 실제 Android 설치 여부는 기기에서 확인해야 합니다. 설치가 안 되면 HTTPS 인증서 경고가 없는지 먼저 확인합니다. 설치만으로 오프라인 EPUB 읽기가 제공되지는 않습니다.

공식 설치 조건: https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable

## 전체 페이지 번호로 이동

기존 하단 페이지 표시 자리에 **현재 / 전체 화면 페이지**를 표시합니다. 숫자를 터치하거나 클릭하면 **전체 페이지로 이동** 팝업이 열립니다. 현재 화면·글꼴 기준으로 계산하며, 하단 오른쪽에 표시합니다. 기존 콘텐츠 파일 번호는 화면에서 숨기고 원래 페이지 이동 처리는 내부적으로 유지합니다.

같은 높이의 좌측 하단에는 **현재 목차 제목**, 우측 하단에는 **현재/전체 페이지 (진행률%)**를 표시합니다(예: `183/450 (40%)`). 진행 막대는 표시하지 않습니다. 진행률은 같은 전체 화면 페이지 계산을 사용하며 마지막 페이지는 100%입니다. 리더 설정의 글자 크기 아래 **목차·진행률 표시**에서 켜고 끌 수 있습니다(기본 켜짐). 설정은 이 브라우저의 계정별로 보관하며, 끄면 목차·퍼센트와 집중 모드의 우측 하단 페이지 표시를 숨기고, 메뉴가 보일 때는 하단바 가운데에 실제 페이지 숫자·페이지 이동만 유지합니다. 목차 제목은 진행률 영역을 제외한 가로 공간을 사용하고, 그보다 길 때만 줄여 표시하며, 목차 정보가 없으면 본문 제목 또는 ‘목차 없음’을 표시합니다.

- 전체 계산이 끝나 숫자가 표시된 상태에서 사용할 수 있습니다. `계산 중` 또는 `—` 상태와 로딩/다른 팝업이 열린 동안에는 사용할 수 없습니다.
- 1부터 표시된 전체 페이지 수까지의 정수만 허용하며, 취소하면 현재 위치를 유지합니다.
- 기존 Kavita 페이지 이동 팝업과 장 전환을 사용하고, 해당 장이 로드된 뒤 장 안의 화면 위치를 맞춥니다. 긴 장이나 이미지 로딩에서는 잠깐 시간이 걸릴 수 있습니다.
- 몰입 모드에서 메뉴가 숨겨져 있어도 사용할 수 있으며, 이동/취소 후 메뉴를 다시 숨깁니다.
- 팝업이 열린 동안 화면 크기·글꼴·레이아웃이 바뀌면 팝업을 닫고 재계산 후 이동하세요. 이동 준비 중 새 읽기 조작을 하면 지연된 화면 이동을 취소합니다.
- 기존 리더의 진행 상태 저장을 사용하며 추가 진행 저장 API를 만들지 않습니다. 페이지 계산 캐시는 기존처럼 14일간 유지합니다.

검증: Chromium에서 같은 장/다른 장, 첫·마지막 페이지, 입력 오류, Enter/취소, 1열/2열, 몰입 모드 및 기존 읽기 위치 테스트를 확인했습니다. 실제 Kavita의 `브람스를 좋아하세요`에서도 13·14페이지, 첫·마지막 페이지 및 몰입 모드 이동을 확인했습니다. 테스트 브라우저의 API 쓰기는 차단했습니다. 실제 Android는 새로고침 후 숫자를 눌러 이동하고 기존 스와이프·메모·읽기 위치도 확인하세요.

## 높이에 따라 페이지 넘기기

새로고침 후 EPUB 리더의 설정 메뉴를 엽니다. 글자 크기 바로 아래의 **높이에 따라 페이지 넘기기**를 켜세요. 기본값은 꺼짐입니다.

- 화면 좌우 각 20%에서 위쪽 1/3을 탭/클릭하면 이전 페이지, 아래쪽 2/3이면 다음 페이지입니다. 높이 기준은 현재 브라우저 화면입니다.
- 가운데 60%는 기존 메뉴 동작을 유지합니다. 상하 메뉴 버튼은 원래 기능으로 동작합니다.
- 기존 터치 페이지 넘김 옵션과 독립적으로 동작합니다. 끄면 기존 좌우 영역 동작으로 복구됩니다.
- EPUB 1열/2열에 적용합니다. PDF와 세로 스크롤 모드에는 적용하지 않습니다.
- 선택 중인 텍스트, 링크, 입력, 북마크/하이라이트/각주 컨트롤, 설정·목차·메모 팝업, 로딩, 드래그, 두 손가락 터치는 페이지 넘김 대상에서 제외합니다. 기존 스와이프 방향은 그대로 유지합니다.
- 설정은 같은 사이트/브라우저에서 계정별로 저장합니다. 다른 기기에는 자동 동기화되지 않으며, 브라우저 저장소가 차단되면 현재 탭에서만 유지됩니다.

Android/Windows/Ubuntu 터치 브라우저와 PC 마우스에서 위쪽 좌우, 아래쪽 좌우, 가운데 메뉴, 몰입 모드, 옵션 끄기를 확인하세요. Chromium 자동 테스트로 영역 경계와 충돌 방지를 검증하며 실제 Android 확인은 별도로 필요합니다.

## 확인한 환경과 변경

현재 프로젝트는 `/home/achops1368/docker/kavita`이며, 원본 `compose.yaml`은 그대로 보관했다. Windows D:의 books/config가 각각 `/mnt/d/Kavita/books`, `/mnt/d/Kavita/config`에 마운트된다. 운영 컨테이너는 `kavita`, 호스트 포트는 5000, 재시작 정책은 `unless-stopped`이다. 버전 캐시에 기록된 CurrentVersion은 0.9.1.4이며 실행 이미지 커밋은 `d77d956b9551227d8be2ee488b08f14aa3a341e5`다.

동일 커밋의 EPUB 리더 소스에는 탭 페이지 넘김과 텍스트 선택 처리가 있지만 수평 스와이프 페이지 전환은 없다. 본문은 iframe이 아닌 `.book-content`에 렌더링된다. 기존 페이지 버튼은 `movePage()`를 호출하므로 스크립트가 그 버튼을 클릭한다. 키보드 이벤트와 데이터 API는 사용하지 않는다. 소스: https://github.com/Kareadita/Kavita/tree/d77d956b9551227d8be2ee488b08f14aa3a341e5/UI/Web/src/app/book-reader

별도 `compose.swipe.yaml`은 현재 Kavita 이미지를 digest로 고정하고, 호스트 5000 포트를 Nginx에 배정한다. Kavita는 동일 Compose 네트워크의 내부 5000 포트로 접근한다. 책/config 마운트와 계정 데이터는 그대로 사용한다. 이 파일은 원본과 합치는 override가 아니라 독립 Compose 파일이다. 두 파일을 함께 `-f`로 지정하지 않는다.

Nginx는 HTML에 동일 출처의 `/kavita-swipe.js`를 삽입한다. upstream 압축을 끄고 원래 경로, 쿼리, Host, 인증 헤더 및 쿠키를 전달하며 WebSocket upgrade도 전달한다. 현재 CSP는 `frame-ancestors 'none'`이므로 스크립트 삽입을 차단하지 않는다. CSP를 삭제하거나 완화하지 않는다. SPA 경로는 Kavita로 그대로 전달한다. 향후 CSP 또는 DOM이 바뀌면 재검증해야 한다.

스크립트는 OS나 User-Agent로 제한하지 않으며, Touch Events를 전달하는 Android·Windows·Ubuntu 등의 터치스크린 브라우저에서 실행된다. 한 손가락, 70px 이상, 수평/수직 비율 2 이상, 수직 이동 35px 이하, 1200ms 이내의 제스처만 처리한다. 전환 뒤 650ms 동안 스와이프에서 파생된 클릭을 차단한다. 새 스와이프와 탭은 공통 대기열에서 순서대로 처리한다. 시작점이 좌우 가장자리 32px 이내면 브라우저 제스처에 맡긴다. 세로 스크롤 모드, PDF, 텍스트 선택, 입력 요소, 설정/목차/메모 drawer, 팝업, 로딩, 다중 터치에서는 동작하지 않는다. 긴 누르기는 선택을 위해 제외한다. 마우스 드래그나 키보드 입력으로 스와이프를 인식하지 않는다. 터치가 없는 PC에서는 기존 조작을 유지한다. 브라우저가 터치를 마우스 이벤트로만 전달하면 스와이프를 사용할 수 없다.

**사용 조건:** EPUB 레이아웃을 1열 또는 2열로 설정한다. 몰입 모드에서 메뉴가 숨겨져 있어도 스와이프를 처리한다. 본문에 기존 메뉴 토글용 mousedown/click 이벤트를 전달해 페이지 버튼을 생성하고, 기존 페이지 버튼을 클릭한 뒤 메뉴를 다시 숨긴다. 이 과정에서 메뉴 요소는 CSS로 가려 깜빡임을 줄인다. 메뉴 표시/숨김으로 리더의 레이아웃 측정이 발생할 수 있으므로 실제 기기에서 위치와 장 경계를 확인한다. 선택이나 팝업이 처리 중 생기면 페이지 전환을 취소하고 추가 메뉴 토글도 하지 않는다. 읽기 방향과 무관하게 왼쪽 스와이프는 `next-page-highlight`가 붙은 다음 버튼을 클릭한다. DOM이 달라져 버튼을 확인할 수 없으면 동작하지 않는다. 일부 기기의 브라우저 제스처 범위는 32px보다 클 수 있다.

## 백업

`backups/LATEST`에 검증한 백업 폴더명이 기록되어 있다. 해당 폴더에는 원본 Compose, config 전체 압축파일, SQLite 온라인 백업, SHA-256 체크섬이 있다. SQLite `integrity_check`와 압축파일 전체 읽기를 통과했다. 실행 중 변경되는 일반 로그/cache 파일은 단일 시점 스냅샷이 아니며, 각 DB는 별도로 일관성을 확보했다. 백업에는 민감한 계정 정보가 있으므로 외부에 공개하지 않는다. 책 파일은 변경하지 않았다.

## 배포 — 운영 변경 승인을 받은 뒤 실행

배포는 Kavita 컨테이너를 재생성하고 5000 포트를 프록시로 옮기므로 잠깐 접속이 끊긴다. 프로젝트 이름을 반드시 `kavita`로 유지한다. 원래 SSH 포트포워딩의 원격 포트 5000은 유지한다.

```bash
cd /home/achops1368/docker/kavita
docker compose -p kavita -f compose.swipe.yaml config --quiet
docker compose -p kavita -f compose.swipe.yaml up -d --pull never
docker compose -p kavita -f compose.swipe.yaml ps
curl -fsS http://localhost:5000/api/health
curl -fsS http://localhost:5000/ | rg kavita-swipe.js
curl -fsS http://localhost:5000/kavita-swipe.js | head
```

프록시 이미지가 없다면 먼저 `docker pull nginx:stable-alpine`을 실행한다. 새 주소가 아니라 기존 주소로 접속한다. 사용 중인 터치스크린 브라우저에서 페이지를 새로고침한다. 삽입이 적용되지 않으면 기존 사이트 탭을 닫고 다시 열거나 캐시만 비운다. 사이트 데이터 전체 삭제는 필요하지 않다.

## 수동 회귀 테스트

1. 배포 전에 테스트 EPUB의 현재 위치와 기존 하이라이트/메모를 기록한다. 로그인 계정의 기본 읽기 모드는 incognito가 아니어야 한다.
2. Android Chrome 및 사용 중인 Windows·Ubuntu 터치스크린 브라우저 각각에서 1열 모드에서 몰입 모드를 켠 상태와 끈 상태 각각으로 본문 중앙을 빠르게 왼쪽으로 70px 이상 스와이프한다. 정확히 한 페이지 진행하고 오른쪽은 이전 페이지로 돌아오는지 확인한다. 2열과 장 경계도 확인한다. 몰입 모드에서 메뉴가 숨겨진 상태로 좌우 스와이프를 반복하고, 한 번에 한 페이지만 넘어가며 메뉴가 계속 숨겨져 있는지 확인한다. 본문 탭으로 메뉴를 다시 표시할 수 있는지도 확인한다.
3. 짧은 이동, 수직/대각 이동, 좌우 가장자리 시작, 두 손가락, 긴 누르기, 텍스트 선택, 하이라이트 도구, 메모 작성, 목차, 설정, 팝업에서 페이지가 넘어가지 않는지 확인한다. 탭 페이지 넘김을 켠 상태에서도 한 번만 넘어가는지 확인한다.

## 업데이트와 자동 실행

현재 Kavita와 Nginx를 digest로 고정했으므로 `pull`만으로 버전이 올라가지 않는다. 업데이트 전에 config 온라인 백업을 다시 만들고 새 버전의 EPUB DOM, CSP, 다음 버튼 표시와 모든 수동 회귀 항목을 검증한 뒤 digest를 바꾼다. `latest`로 임의 교체하지 않는다. Nginx 업데이트는 `docker pull nginx:stable-alpine` 후 `docker image inspect nginx:stable-alpine --format '{{json .RepoDigests}}'`로 새 digest를 확인하고 Compose에 반영한 뒤 프록시를 재생성하고 응답/주입을 확인한다.

WSL `/etc/wsl.conf`의 `systemd=true`, Docker 서비스 `enabled`를 확인했다. 두 컨테이너 모두 `unless-stopped`이므로 Docker가 시작되면 재시작한다. Windows의 기존 WSL 시작 예약 작업 및 재부팅 자체는 검증하지 않았다. Windows 재부팅 후 WSL 실행, D: 마운트, Docker 활성 상태, 두 컨테이너 상태와 원래 SSH 터널을 확인한다. 기존 자동 실행 스크립트가 `compose.yaml up -d`를 실행한다면 승인된 배포 후 `compose.swipe.yaml`을 사용하도록 수정해야 한다. 단순 WSL/Docker 시작 스크립트라면 변경이 필요 없다.

## 책 전체 화면 페이지 표시

하단에는 문구 없이 `현재 페이지 / 전체 페이지` 숫자만 표시한다. 오른쪽 아래에 배치하며 기존 하단 Page 표시·화살표 메뉴가 보이면 메뉴 전체의 위쪽으로 올려 겹치지 않게 한다. 몰입 모드에서도 표시한다.

전체 페이지는 현재 EPUB 파일(Kavita chapterId)의 모든 spine 구간을 대상으로 한다. 시리즈의 다른 EPUB 파일은 포함하지 않는다. 2열에서는 한 번 넘기는 화면을 한 페이지로 센다. 화면 크기·글꼴·여백·레이아웃 변경 후 다시 계산하며 페이지 번호는 고정된 종이책 쪽수가 아니다.

리더의 기존 GET 요청에서 현재 파일·구간과 인증 헤더를 메모리로만 관찰한다. `/api/book/{id}/book-info`의 pages 값으로 모든 구간을 확인하고, 구간별 `/book-page?page=`를 읽기 전용으로 조회한다. 같은 화면 크기·리더 CSS·글꼴·여백을 적용한 화면 밖의 sandbox iframe에서 구간을 차례로 배치해 페이지 수를 합산한다. 이미지·글꼴 로딩을 기다린다. 현재 구간은 실제 리더 측정값을 사용하고 전체 위치는 앞 구간 합계에 현재 화면 번호를 더한다. iframe에는 스크립트를 허용하지 않으며, 측정 후 제거한다. 책 본문은 현재 탭 메모리에만 유지하고, 계산된 페이지 숫자는 브라우저 캐시에 보관하며 인증 헤더를 로그나 저장소에 기록하지 않는다. 읽기 위치/메모/하이라이트 저장 API는 호출하지 않는다.

다시 열 때 완료한 캐시는 즉시 재사용하고, 중단된 계산은 저장된 구간부터 이어서 계산한다. 부분 결과도 캐시로 저장한다. 최초 구간별 계산에서 20ms의 인위적 대기를 제거하고 이벤트 루프에 한 번 양보하도록 변경했다. 첫 계산과 새 설정의 계산은 여전히 전체 구간을 배치하므로 시간이 필요하다. 캐시는 같은 브라우저·사이트 주소에서 재사용하며 다른 기기나 브라우저에는 동기화하지 않는다. 브라우저 사이트 데이터를 지우면 캐시도 사라진다.

읽기 위치 보완: 기존 Kavita의 `reader/progress` POST에 담기는 본문 XPath 뒤에, 같은 요소를 가리키는 유효한 XPath 조건으로 화면 설정 해시와 구간 내 화면 위치를 함께 저장한다. 예전 위치 문자열은 그대로 지원한다. `reader/get-progress` 응답에서 보완 정보가 있으면 네이티브 XPath 복원이 끝난 뒤 동일 화면 설정에서 화면 위치를 복원한다. 초기 복원 과정의 위치 저장은 정확한 화면 정보를 덮어쓰지 않게 보호한다. 본문 선택/메모 데이터, API 엔드포인트, DB 스키마를 바꾸지 않고 추가 POST도 만들지 않는다. 기존 계정의 위치 저장 경로를 사용하므로 수정 기능이 적용된 클라이언트에서도 읽기 위치를 받을 수 있다. 폰트·화면 설정이 다르면 기존 본문 요소 기반 복원을 사용한다.

이 변경 이후 저장한 위치부터 정확한 화면 위치 정보가 포함된다. 이미 장 시작으로만 저장된 예전 기록의 잃어버린 화면 위치는 자동 복구할 수 없다. 새로고침 후 몇 페이지 읽고 리더를 정상 종료해 다시 열어 확인한다. 저장 없이 브라우저를 강제 종료하거나 네트워크가 끊기는 상황까지 보장하지 않는다. Chromium fixture에서 긴 단락의 화면 위치 저장/재열기, 초기 저장 덮어쓰기 방지, 유효한 XPath, XHR/fetch POST 보완, 추가 저장 요청 없음과 14일 캐시를 검증했다. 실제 Android·기존 계정 책의 회귀 검증은 남아 있다. 변경 전 JS와 온라인 DB 백업은 `backups/reading-position`에 보관했다.

첫 계산 최적화: 계산 세션마다 숨겨진 iframe과 공통 CSS를 한 번만 준비하고 구간 본문을 교체해 재사용한다. 구간별 본문 CSS는 교체 시 제거해 다음 구간에 남지 않게 한다. 본문은 최대 2개 요청을 동시에 미리 받아 다음 구간의 네트워크 대기와 현재 구간 측정을 겹친다. 페이지 측정 자체는 순서대로 진행한다. 화면 resize, 설정/책 변경, 리더 종료 시 계산을 취소하고 진행 중인 GET 및 iframe을 정리한다. 취소는 오류 표시로 취급하지 않으며 새 설정에서 부분 캐시/본문 메모리를 활용해 다시 시작한다. 14일 숫자 캐시는 그대로 사용한다.

높이에 따라 페이지 넘기기 옵션에서 새 탭은 650ms 대기 없이 받습니다. 스와이프 뒤에 발생하는 중복 클릭 차단은 유지하고, 새로운 포인터 누름/해제가 확인된 탭은 별도로 처리합니다. 기본 좌우 탭 옵션을 변경하지 않으며 스와이프 인식 조건도 유지합니다.

페이지 버튼 처리는 한 번씩 직렬 실행합니다. 장 로딩 중 추가 탭을 최대 3개 대기시키며, 현재 실행 중인 한 번을 포함하면 최대 4번입니다. 입력한 다음/이전 방향 순서를 유지하고 10초가 지난 대기 입력은 버립니다. 가운데 영역, 링크/입력/설정 조작, 드래그·선택·다중 터치, 리더 종료·책 주소 변경 시 대기 입력을 취소합니다. 로딩 도중 가운데 탭은 대기만 취소하고 임시 메뉴를 토글하지 않습니다. 전환 완료 후 가운데 탭으로 기존 메뉴를 열 수 있습니다.

Chromium에서 0.14초 간격 4회 탭, 3개 대기 한도, 느린 장의 순차 처리, 방향 순서, 대기 취소와 집중 모드 유지, 기존 페이지 번호 이동·읽기 위치 복원을 검증했습니다. 실제 Android에서는 사이트 새로고침/PWA 재실행 후 확인하세요.

### 2026-10-14 빠른 연속 스와이프

스와이프의 650ms 간격 제한과 전환/로딩 중 입력 무시를 제거했습니다. 완료된 스와이프 한 번을 하나의 요청으로 등록하고, 탭과 같은 대기열에서 순서대로 처리합니다. 높이별 탭 옵션이 꺼져 있어도 스와이프 대기열은 동작합니다.

공통 대기 한도는 추가 입력 3개이며 탭/스와이프 각각 3개가 아닙니다. 수평 70px, 수평/수직 비율 2 이상, 수직 이동 35px 이하, 1.2초 이내, 한 손가락, 가장자리 32px 제외 조건은 유지합니다. 손가락을 움직이는 중에는 페이지를 넘기지 않고 종료 이벤트에서 한 번만 등록합니다. 세로 이동·다중 터치·선택·팝업·리더 종료 등은 대기 입력을 취소합니다. 스와이프 뒤 발생하는 클릭 차단과 집중 모드 유지도 그대로 적용합니다.

Chromium 실제 터치 입력으로 연속 4회, 탭 옵션 켜짐/꺼짐, 느린 장 로딩, 대기 상한, 탭·스와이프 방향 순서와 세로/가장자리 취소를 검증했습니다. 기존 페이지 번호 이동·높이별 탭·집중 모드 테스트도 통과했습니다. 실제 Android 확인은 새로고침/PWA 재실행 후 수행하세요.

오프라인 통합 리더: 저장한 EPUB도 온라인과 같은 Angular 리더·설정창·목차·메모 편집기를 사용합니다. 준비는 최상위 페이지에서 진행하여 기존 CSP의 `frame-ancestors` 정책을 유지합니다. 공개 코드만 HTTP 캐시하고 개인 데이터는 계정별 IndexedDB로 제공합니다. 일반 온라인 API 동작은 유지합니다. 사용법·지원 범위·롤백은 [OFFLINE.md](OFFLINE.md)를 참고하세요.
